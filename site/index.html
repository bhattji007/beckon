How it works

  1. 1

    Download

    Open the dmg and drag Beckon to Applications. It lives in your menu bar; there is no window to manage.

  2. 2

    One-click hook install

    On first launch Beckon shows exactly which hook entries it will add to ~/.claude/settings.json and asks for one click. Existing hooks are kept, a backup is saved, and running sessions pick it up instantly.

  3. 3

    Answer from the overlay

    Allow, deny, pick an option or type a reply on the card. ⌥Space focuses the top card, Esc hands you back. Dismiss a card and Claude’s normal prompt appears in the terminal.

Many sessions, one place. One card per request, newest on top, colour per project, host app shown as a chip.
Only when you’re away. If the terminal that asked is already in front, Beckon stays quiet.
Never steals focus. Cards appear without taking the keyboard; you opt in with a hotkey or a click.
Logged. Every decision is appended to ~/.beckon/log.jsonl. No private allow-lists.

FAQ

What does it require?

macOS 14 (Sonoma) or newer, on Apple silicon or Intel, and Claude Code. No Accessibility, Screen Recording or Input Monitoring permissions are needed.

Which terminals and editors does it work with?

Any terminal (Ghostty, iTerm2, Terminal.app, Warp, kitty, WezTerm…), the VS Code and JetBrains extensions, and Claude Desktop. Hooks in ~/.claude/settings.json run in all of them, and that is all Beckon relies on.

What happens if Beckon isn’t running?

If Beckon isn’t running, Claude Code works exactly as before. The hook is a tiny shim that exits immediately when it can’t reach the app, so Claude falls back to its normal terminal prompt. Quitting Beckon releases every held prompt first. Beckon can never make Claude Code worse.

Does it phone home? What about my commands and code?

No. Beckon makes no network connections except a periodic update check that fetches a small JSON file (this one) to tell you when a new version exists; nothing is sent, and nothing installs itself. The text shown on cards comes from the hook payload on your machine and stays there. The socket in ~/.beckon is user-only.

Does it auto-approve anything?

Never. “Always” writes a regular Claude Code permission rule to the project’s .claude/settings.local.json, so it is visible to and honoured by Claude Code even with Beckon off. Hover the button to see the exact rule before you click.

macOS says the app “can’t be verified” or is “damaged”. What now?

Release builds are signed with a Developer ID and notarized by Apple, so you should only see this on a preview or self-built copy. If you do:

  1. Try to open Beckon once; dismiss the dialog (choose “Done”, not “Move to Trash”).
  2. Open System Settings → Privacy & Security, scroll to the Security section and click Open Anyway next to the Beckon message. Confirm with Touch ID or your password.
  3. Older systems: right-click (Control-click) Beckon.app in Applications and choose Open.

If macOS calls the file “damaged”, the quarantine flag is in the way. In Terminal run xattr -dr com.apple.quarantine /Applications/Beckon.app and open it again. Only do this for a download whose SHA-256 matches the one on the release page.

How do I uninstall?

Choose “Remove hooks” from the menu-bar menu (it removes exactly the entries it added), quit Beckon and drag it to the Trash. Optionally delete ~/.beckon.
